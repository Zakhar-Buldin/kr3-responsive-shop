# Музыкальная школа «Аккорд» — КР №3

**Тема:** «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

**Автор:** Бульдин Захар Андреевич, ЭФБО-01-25.

Проект продолжает КР №1 из предоставленного архива `kr1-html-css-shop.zip`.
Сохранены музыкальная школа, направления (гитара, фортепиано, вокал), тексты,
фотографии, фиолетовая палитра, БЭМ-классы и основные страницы. Bootstrap и другие
CSS-фреймворки не используются. КР №2 не является основой этого проекта.

## Запуск

Откройте `index.html` в браузере. Сайт работает без сборки и установки библиотек.
Для Lighthouse рекомендуется локальный HTTP-сервер:

```bash
python -m http.server 8000
```

Откройте `http://localhost:8000`. Шрифт названия школы загружается из Google Fonts,
как в КР №1; при отсутствии интернета используется системный cursive.
Все фотографии и скрипты хранятся локально.

## Адаптивность и контрольные точки

Базовые правила рассчитаны на мобильный экран. Расширения добавляются через
`@media (min-width: ...)`. Контрольные точки выбраны по содержимому сайта.

| Ширина | Что меняется |
|---|---|
| До 640 px | Одна колонка карточек и полей; меню по кнопке; фильтры над курсами; таблица в виде карточек характеристик |
| От 640 px | Две карточки в строке, преимущества в две колонки, обычная таблица |
| От 768 px | Горизонтальное меню, двухколоночная форма на страницах заявки и контактов |
| От 900 px | Текст и фотография рядом в hero и описании курса |
| От 1100 px | Три карточки; боковая панель фильтров со sticky-позиционированием |

Flexbox используется в шапке, навигации, карточках и группе кнопок.
Grid — в каталоге, hero, описании курса, форме и сетке направлений.
`minmax(0, 1fr)` и `min-width: 0` позволяют колонкам сжиматься без переполнения.
`clamp()` плавно меняет размер заголовков. Горизонтальный скролл всей страницы
не скрывается через `overflow-x: hidden`: ширины элементов исправлены.

## Адаптивные изображения

Для каждой исходной фотографии подготовлены реальные WebP-файлы шириной 360 и
720 пикселей. `picture` предлагает WebP через `source`; JPEG внутри `img` остаётся
запасным вариантом. `srcset` перечисляет ширины, `sizes` описывает размер в макете.
Браузер учитывает ширину экрана и плотность пикселей, поэтому на телефоне с высоким
DPR может выбрать файл 720 px — это нормально.

У изображений указаны `width` и `height`, `max-width: 100%`, `height: auto`.
Фотографии ниже первого экрана используют `loading="lazy"`; главное изображение
загружается сразу. `object-fit: cover` сохраняет пропорции при кадрировании.

## Доступность и исправления относительно КР №1

- Добавлена первая ссылка «Перейти к содержимому»; появляется при Tab и переводит фокус в `main`.
- На каждой странице один `h1`; страница курсов получила общий заголовок, названия курсов — `h2`.
- Текущая страница обозначена `aria-current="page"`.
- Кнопка меню имеет `aria-controls` и обновляемый `aria-expanded`; Escape из меню возвращает фокус на кнопку.
- У интерактивных элементов видимый фокус, у полей — связанные подписи; обязательные поля отмечены звёздочкой.
- Подсказка телефона связана с полем через `aria-describedby`. Убрана жёсткая маска, требовавшая точных скобок и дефисов.
- Для диалога используется нативный `dialog`, понятный заголовок, верхняя кнопка закрытия, Escape, замкнутый Tab/Shift+Tab и возврат фокуса на кнопку открытия.
- Выбранный курс автоматически подставляется в диалог и показывается текстом.
- В таблицах сохранены `caption`, `th`, `scope`; при мобильной перестройке явные роли сохраняют назначение строк и ячеек.
- Подтверждения форм используют `role="status"`; цвет успешного сообщения затемнён для читаемости.
- Учитывается `prefers-reduced-motion`: плавная прокрутка отключается при системном уменьшении движения.
- Без JavaScript навигация остаётся открытой; для каталога используется нативный `details`.

## Самостоятельные доработки сверх базовой инструкции

1. Мобильное меню с клавиатурным управлением и корректным переходом между ширинами.
2. Сворачиваемые фильтры на телефоне, боковой фильтр на большом экране, рабочий отбор по категории и цене, счётчик, пустое состояние и сброс.
3. Таблицы превращаются в читаемые карточки характеристик на телефоне, а не только прокручиваются вбок.
4. Несколько responsive images с настоящими WebP-вариантами для трёх направлений и hero.
5. Доступное модальное окно, skip-link, улучшенные формы, обратная связь на странице контактов.
6. Проверены все пять страниц; сохранены отдельные отчёты, скриншоты и результаты браузерной проверки.

## Проверки

Пять страниц проверены на ширинах **360, 430, 768, 1024 и 1440 px** — всего
25 сочетаний. Не обнаружены горизонтальное переполнение страницы, битые изображения,
поля без подписи и дублирующиеся ID. На каждой странице один `h1`.

Браузерная проверка также проверяет skip-link, меню, Escape, удержание и возврат
фокуса диалога, подстановку курса, фильтры, пустое состояние, сброс, отклонение
пустой формы и подтверждение корректной. Результат: `lighthouse/browser-checks.json`.

### Lighthouse

Локальная проверка в Chrome, Lighthouse 13.6.0, категория Accessibility, мобильный
режим. Точная дата и версия браузера записаны в JSON-отчётах (`fetchTime`, `environment`).

| Страница | Accessibility | Отчёт |
|---|---:|---|
| Главная | 100/100 | [index](lighthouse/index-accessibility.html) |
| Каталог | 100/100 | [catalog](lighthouse/catalog-accessibility.html) |
| Курсы | 100/100 | [product](lighthouse/product-accessibility.html) |
| Запись | 100/100 | [order](lighthouse/order-accessibility.html) |
| Контакты | 100/100 | [contacts](lighthouse/contacts-accessibility.html) |

100/100 относится к автоматическим проверкам и не является гарантией полной
доступности. Дополнительно проверены клавиатурные сценарии и просмотрены скриншоты.
Проверка настоящим экранным диктором не выполнялась.

### Как повторить вручную

1. Открыть все страницы в DevTools на пяти заданных ширинах.
2. Нажать Tab: проверить skip-link и видимость фокуса. Пройти меню без мыши.
3. Открыть запись с карточки: проверить выбранный курс, Tab, Shift+Tab, Escape и возврат фокуса.
4. На странице курсов сравнить характеристики при 360 и 768 px.
5. В каталоге выбрать «Вокал», применить фильтр, затем цену до 1000 и сброс.
6. Проверить пустую форму и корректное заполнение. Все подтверждения — демонстрационные.
7. Во вкладке Network с фильтром Img и отключённым кэшем сравнить загруженные WebP на разных ширинах.
8. В Lighthouse выбрать Accessibility, запустить аудит и сравнить с сохранённым отчётом.

## Ограничения учебного проекта

Backend отсутствует. Формы не отправляют данные, корзина и хранение в localStorage
не реализуются в КР №3. Контакты школы — учебные. JavaScript используется только
для небольших интерфейсных сценариев; основной предмет работы — HTML/CSS и A11y.

## Git, Pull Request и публикация

Создан самостоятельный локальный Git-репозиторий. Первый коммит содержит исходную
КР №1; доработки выполнены в ветке `codex/kr3-responsive-accessibility`.
В `.github/pull_request_template.md` подготовлено описание изменений и проверок.

**На момент подготовки сайт ещё не опубликован, удалённый репозиторий и Pull Request
не созданы.** Для сдачи нужно создать на GitHub репозиторий `kr3-responsive-shop`,
отправить `main` и рабочую ветку, открыть и объединить Pull Request. Затем включить
GitHub Pages из `main`, папка `/ (root)`, проверить сайт и добавить сюда полученную ссылку.
В СДО сдаётся ссылка на репозиторий; публикация даёт отдельные 0,4 балла по методичке.
